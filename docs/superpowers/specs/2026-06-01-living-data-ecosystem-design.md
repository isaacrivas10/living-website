# The Living Data Ecosystem — Design Spec

**Date:** 2026-06-01
**Status:** Approved design, ready for implementation planning

## Overview

An interactive capability showcase for Argo Analytics, built for a competition that rewards visible, well-documented AI workflows. Rather than describing what Argo does, the site *performs* it: an interactive canvas of capability nodes where drilling into a node opens a surface that generates a live, self-contained artifact from a local LLM. The user mutates that artifact with natural language, watching the AI rebuild it.

The guiding principle is maximal AI authorship made reliable by cheap local inference. Every surface a visitor sees inside a node is generated by the model, not templated. Reliability comes from a generate-render-repair loop rather than from constraining what the AI can produce.

## Scope

Three nodes, built deep rather than broad. No fourth node.

- **Domo (hero node).** Natural language builds a BI-style visualization, e.g. "monthly revenue by region with anomaly detection." This is the most immediately legible demo — type a sentence, get a dashboard — and it maps to Argo's core offering, which is fundamentally a Domo shop. Gets the most polish and a second seed.
- **Data Engineering (architecture blended in).** Generates an interactive lineage/pipeline DAG (source → staging → intermediate → BI) *and* the transformation code beside it, both mutated by the same parameter: "switch the source connector from API to Kafka" reshapes the diagram and regenerates the connector code; "add incremental loading" annotates the DAG and updates the dbt snippet. This is the credibility and depth node — it carries both the design view and the engineering view in one place.
- **AI/ML.** Natural language generates a mock model dashboard with a performance chart and an explanation, e.g. "predict churn for retail."

## Architecture

A local two-tier application.

- **React frontend** owns the canvas, the node surfaces, and all chrome. This layer is fully deterministic — nothing here is AI-generated.
- **FastAPI backend** owns everything model-facing: prompt assembly, the repair loop, the cache, and serving seeds. It proxies to the local model's OpenAI-compatible endpoint on localhost.
- **Model:** Qwen3.6-35B-A3B running locally (via Ollama, vLLM, or LM Studio). Its low active-parameter count makes fresh generations cheap enough to run an aggressive repair loop.

The deterministic shell and the unpredictable AI output stay cleanly separated: all generated content is confined to sandboxed iframes, so nothing the model produces can break the navigation.

## Components

Each component has a single purpose and a well-defined boundary.

**Canvas** (React, deterministic). Three hand-placed nodes in a fixed composition, with zoom and pan, light ambient motion, and triangular/geometric node forms echoing the Argo logo mark. The core interaction is drill-down: zooming into a node transitions into its surface, a spatial metaphor for drilling into data. No frequency-based glow and no persisted exploration history.

**Node surface** (React). What the visitor lands in after drilling into a node. Contains a sandboxed iframe that renders the generated HTML, the parameter controls (curated quick-action chips plus a free-text box), a "Show prompt" toggle, and a visible "building" pane that streams the raw HTML as it generates.

**Generation service** (FastAPI, one endpoint). Takes `{node, prompt}`. Assembles the full prompt — the node-specific system prompt carrying the shared Argo design tokens, plus the chip or free-text prompt — calls the local model, streams the output, runs the repair loop, and returns a single self-contained HTML document.

**Repair loop** (coordinated between service and client). Validation is two-stage. The backend does a cheap syntactic sanity check before sending. The client does the authoritative render check: the finished document is loaded into the sandboxed iframe, and the iframe reports success or failure via `onerror` / a postMessage health-check. On render failure, the error context is fed back to the model and it regenerates, capped at N attempts. After N failures, the surface falls back to the node's pinned seed.

**Cache and seeds** (FastAPI, on-disk). One store of validated generations keyed by `{node, hash(normalized_prompt)}`, holding the final HTML, the prompt used, and timing. A `pinned` flag marks the launch default and fallback per node; pinned entries are the seeds and are never evicted. Only successful, post-repair output is ever cached — never failures. A startup pre-warm script runs each curated chip once and pins the good result, which is also how seeds are produced, so seed generation and cache warming are the same step. One seed per node, two on the hero (Domo).

**/process page** (React, static, tight scope). The competition scoring surface. Documents the prompt structure, the repair-loop approach, the tool chain, and before/after notes on AI output versus polished result. Reinforced by the live "Show prompt" toggle elsewhere on the site.

## Data flow (one interaction)

1. Visitor drills into a node; its pinned seed renders immediately in the iframe.
2. Visitor clicks a curated chip or types in the free-text box.
3. Frontend POSTs `{node, prompt}` to the generation service.
4. Backend assembles the full prompt and streams the model's raw HTML into the visible "building" pane — this is the live-generation theater.
5. On completion, the *finished* document is rendered into the sandboxed iframe. Half-streamed HTML is never rendered.
6. Render success ends the interaction. Render failure enters the repair loop; after N failed attempts, the node's seed is shown.
7. The "Show prompt" toggle reveals the exact assembled prompt for the current surface.

Curated chips serve as demo rails: pre-warmed and pinned, they replay verified-good output instantly, so the walkthrough never depends on a lucky generation. Free text is the openness proof — its inputs vary, so it generates fresh and shows the engine is real.

## Generated artifacts

Every generated surface is a fully self-contained HTML document, including its own fabricated sample data inline. There are no real datasets, no data feeds, and no backend data layer. This keeps every artifact self-contained (which the render path assumes) and is honest for a capability showcase. No user data is stored and nothing is tracked.

## Aesthetic and design tokens

The look relates to Argo's brand but inverts its treatment. Argo's marketing site is light, flat, and conventional; this showpiece is dark, immersive, and depth-forward, so the canvas reads as an instrument rather than a brochure.

- **Dark base** (deep charcoal/navy) with translucent glass panels and real depth and blur.
- **Accents from the Argo brand**: green as primary, yellow as the highlight, teal as tertiary — related to their palette without copying exact values or layout.
- **Triangular/geometric node forms** echoing the logo mark, which also nods to the "Argo" ship/sail identity.
- **Clean, technical typography** and sparse, confident copy matching Argo's plain-spoken voice.

This same palette-and-geometry token block is fed into every generation's system prompt, so AI-built surfaces sit inside the same visual world as the shell instead of clashing with it.

## Entry and exit

A minimal entry screen with one line of orienting copy, then straight onto the canvas — deliberately not a wordless landing, so a judge grasps the value within seconds. A light closing contact CTA in the footer, not a salesy panel.

## Platform

Desktop-only. The demo runs locally on a single machine, so the build targets a desktop experience and does not implement a responsive zoomable canvas. Non-desktop viewports get a simple "best viewed on desktop" notice rather than a degraded interactive layout.

## Error handling

- Broken generated HTML → repair loop (client detects failure, server regenerates with error context, capped at N).
- N failures reached → fall back to the node's pinned seed with a quiet "showing a saved example" state. The demo never hard-fails.
- Model endpoint unavailable → serve the seed plus a clear message.
- Partial/interrupted stream → never rendered; only completed documents reach the iframe.

## Testing

- The deterministic shell — canvas, zoom, drill-down transitions, fallback logic — gets normal interaction tests.
- The generation path is tested at the plumbing level: prompt assembly, the repair-loop logic against a mock model that returns broken-then-fixed HTML, and the fallback-to-seed path.
- Model output quality itself is not unit-testable. It is handled by the seed-curation step — generate, eyeball, freeze the good ones — not by tests.

## Privacy

No user data is stored. Nothing is tracked. All displayed content is AI-fabricated.

## Decisions deferred to the implementation plan

These are implementation details, not open design questions: the exact endpoint request/response schema and node prompt text, the repair-loop attempt cap N, the precise iframe render-success/failure contract, the streaming protocol (intended: SSE), and the canvas zoom/pan library choice.

## Out of scope

The 90-second walkthrough video is a submission deliverable, not part of the application, and is planned separately.

## Success criteria

- Each of the three nodes produces a convincing, on-brand, self-contained AI-generated artifact live.
- Curated chips reliably produce verified-good output via pre-warmed pinned cache entries.
- Free text demonstrably generates fresh, proving open-ended generation.
- The demo never hard-fails, owing to seed fallback.
- The /process page and "Show prompt" toggle make the AI workflow visible and legible to judges.
- The site reads as Argo's world rendered as an interactive artifact, distinct from their marketing site.
